# Data and code: Does Contextual Retrieval Work in Japanese?

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23426281.svg)](https://doi.org/10.5281/zenodo.23426281)

Data, results and code for the report

> Shinji Yumura. **Does Contextual Retrieval Work in Japanese? Testing Anthropic's Method Against Structure-Aligned Chunking in a Production Hybrid RAG.** AQUA Research Technical Report 007, AQUA LLC, 2026.
> Japanese: <https://www.aquallc.jp/research/contextual-retrieval-japanese/>

The study compares Anthropic's [Contextual Retrieval](https://www.anthropic.com/news/contextual-retrieval) (an LLM-written context prepended to each chunk, for both embeddings and BM25) with the counter-claim of [Kuehlkamp et al., arXiv:2610.10170](https://arxiv.org/abs/2610.10170) that structure-aligned chunking beats such contexts, on the Japanese blog (150 articles) behind the assistant YUA, and then measures the production retrieval pipeline before and after switching to chunk-level hybrid retrieval with an LLM reranker.

## Design

| Variant | Chunking | Prepended text |
|---|---|---|
| A | production fixed size (~500 chars) | none |
| As | production chunker, length-matched to C | none (length control) |
| B | as A | LLM context (Anthropic prompt, `gemini-3.5-flash-lite`) |
| C | heading-aligned | none |
| D | heading-aligned | real heading path |
| E | heading-aligned | shuffled heading path (placebo) |
| F | heading-aligned | heading path + LLM context |

Retrieval modes: dense (`gemini-embedding-001`, 3072-d), BM25+ (production tokenizer; `bm25ja` = kuromoji), hybrid RRF (k = 60) with equal weights (`hybrid`), production weights 0.4/1.6 (`hybridProd`) and with the kuromoji BM25 (`hybridJa`); optional LLM listwise reranking of the top 50 (`gemini-3.5-flash-lite`).

Questions: 295 paraphrased questions (`questions.json`; 50 checked by a human, 48 valid; the two flagged are in `drop-flagged.json`) and 150 lexically close questions (`questions-literal.json`), generated by `gemini-3.8-flash` from passages not aligned to any chunk boundary, each with a verbatim evidence sentence. A retrieved chunk counts as relevant if it contains ≥ 70% of the evidence contiguously (whitespace and punctuation ignored).

## Code

| File | Purpose |
|---|---|
| `build-corpus.ts` | re-downloads the articles from the public WordPress API and builds the three chunkings |
| `gen-questions.cjs` | question generation (`STYLE=literal` for the lexically close set) |
| `gen-contexts.cjs` | Anthropic-style contexts (verbatim prompt + "write in the same language as the document") |
| `variants.cjs` | text indexed for each variant |
| `embed.cjs` | embeddings |
| `evaluate.ts` | dense / BM25+ / RRF retrieval and metrics |
| `rerank.cjs` | LLM listwise reranking of the top 50 |
| `analyze.py` | paired tests (McNemar, Wilcoxon, article-clustered bootstrap, Holm) |
| `prod-eval.ts`, `prod-answers.cjs` | measure the production pipeline and its answers |
| `qcheck/` | the human question-check page |

`evaluate.ts` and `prod-eval.ts` import the production tokenizer and search code of YUA, which is not public; they are released as a record of the procedure. The statistics can be reproduced from the released results:

```
mkdir code/out && cp data/results/* data/questions/* code/out/
python code/analyze.py          # writes code/out/analysis.json, identical to analysis/analysis.json
```

(`analyze.py` needs `scipy`.)

## Main results

* Dense: heading-aligned chunks beat Anthropic contexts (nDCG@10 +0.070, Holm p < 0.001).
* BM25: contexts help (+0.030, Holm p = 0.011); real headings beat the placebo (+0.024, Holm p = 0.019).
* Hybrid (equal RRF): no difference between variants.
* LLM reranking of the top 50 halves top-20 failures (18.0% → 9.8%) and removes the differences between variants.
* Production pipeline (document-level, first 25 chunks per article) → chunk-level hybrid + reranking: evidence in context 59.3% → 81.0% (295 q.), 82.0% → 96.7% (150 q.); answers correct 67 → 87 of 100; context ~30,000 → ~4,000 characters; +1.2 s latency.
